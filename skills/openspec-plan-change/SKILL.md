# openspec-plan-change

Scaffold a change folder and produce a task plan using the `openspec` CLI. This is the Dev Manager's core workflow — every change that gets implemented goes through this.

## Prerequisites

```bash
npm list -g @fission-ai/openspec || npm install -g @fission-ai/openspec
cd <project-root>
openspec init   # first time only
```

## When to use

- A proposal exists and needs to be broken into assignable tasks
- Routing work to the right team agent
- Starting the OpenSpec change lifecycle after `/opsx:propose`

## Do not use when

- Requirements are unclear — run `openspec-propose` first
- The change folder already has tasks and an active handoff — use `openspec-handoff` to update state

## Steps

### 1. Bootstrap

Run the `project-bootstrap` skill:

- Read `~/coding-projects/project-map.yaml` → resolve project path
- Read `.ai/shared-memory/current-focus.md`
- Check `openspec/changes/` for existing work

### 2. Check artifact state

```bash
cd <project-root>
openspec status --change "<change-id>" --json
```

This shows which artifacts exist and which are `READY` to generate next.

### 3. Generate missing artifacts

If `tasks.md` was not generated by `/opsx:propose`, generate it:

```bash
/opsx:continue   # generates the next artifact in the dependency chain
```

Or fast-forward all remaining planning artifacts at once (expanded profile):

```bash
/opsx:ff         # generates all remaining artifacts in sequence
```

### 4. Assign owners and set up worktree

Review the generated `tasks.md` and assign roles:

| Situation                  | Assign to      |
| -------------------------- | -------------- |
| API / backend work         | @sr-fullstack  |
| Flutter / mobile           | @mobile-dev    |
| Infrastructure / deploy    | @devops        |
| Architecture design needed | @tech-lead     |
| Requirements unclear       | @product-owner |

Set up one worktree per change (use `git-worktree-discipline` skill):

```bash
git worktree add .worktrees/<change-id> -b feat/<change-id>
```

### 5. Update shared memory

Update `.ai/shared-memory/current-focus.md`:

```yaml
- change-id: <change-id>
  owner: <assigned-role>
  status: in-progress
  phase: implementation
  branch: feat/<change-id>
  worktree: <project-root>/.worktrees/<change-id>
```

### 6. Initialize handoff

Write `openspec/changes/<change-id>/handoff.md` pointing to the first task owner with:

- What they are assigned to do
- Branch and worktree location
- Any known blockers or dependencies

## Done when

- [ ] `tasks.md` exists with named owners and sequence
- [ ] Worktree created and branch set
- [ ] `handoff.md` initialized with first owner
- [ ] `current-focus.md` updated
