# Phase2-T2.2 — Draft candidate and SKILL.md storage

## Status

`done`

## Objective

Persist extracted skill candidates as JSON metadata files and write the generated draft SKILL.md in a format that the existing OpenClaw skills loader accepts.

## Acceptance criteria

- [ ] `writeCandidate()` assigns a UUID id, sets `createdAt`, writes to `learning/candidates/<id>.json`
- [ ] `writeDraftSkill()` writes to `learning/skills/<id>/SKILL.md`
- [ ] Draft SKILL.md has valid frontmatter: `name`, `description`, `metadata` with emoji
- [ ] Draft includes a provenance comment: `<!-- Generated by learning-core | fingerprint: ... | candidate: ... -->`
- [ ] `readCandidate()` throws if file not found
- [ ] `updateCandidate()` uses atomic write-rename
- [ ] `listCandidates()` returns sorted by `createdAt`, filterable by status
- [ ] `SkillCandidate` includes `kind: "new" | "revision"`, `revisesSkillPath?`, `revisesCandidateId?`

## Implementation notes

- Candidate shape: `{ id, fingerprint, toolSequence, sourceSessionKeys, sourceRunIds, createdAt, status, kind, confidence, reasoning, skillName, skillDescription, revisesSkillPath?, revisesCandidateId?, rejectedAt?, rejectedReason?, promotedAt?, promotedTo? }`
- `buildDraftSkillContent()` in `skill-extractor.ts` assembles the SKILL.md string
- Frontmatter uses `metadata: { "openclaw": { "emoji": "🔄" } }` — parsed by `resolveOpenClawMetadata()` in skills loader
- Source: `src/candidate-store.ts`
